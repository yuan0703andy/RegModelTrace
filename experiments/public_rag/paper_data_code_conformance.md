The four released domain files each contain 3,000 rows. Each row has ten nested documents and a unique `index` within its domain; all 30,000 `global_doc_id` values per domain are distinct. Nevertheless, an A0.4 exact-text audit found 397 document-text hashes shared across rows and a connected component of 486 rows. Thus `(domain,index)` cannot safely be treated as an independent split unit. The project-defined split now groups exact-text-connected rows and has zero exact text crossing partitions; see `timely_split/`. The dataset still has no explicit `family_id`, and paraphrase/template leakage remains unmeasured. `global_doc_id` values repeat across domains, so any merged index must namespace IDs by domain.

The pinned `retrieval.py` has two distinct paths. Lines 150–169 choose `alpha_auto` from observable signals. Lines 38–59 and 171–181 choose `best_alpha` by evaluating per-query nDCG against `pos_ids`, i.e. gold labels. `pipeline.py` prints both `auto-α` and `best-α`. The latter is an oracle diagnostic only. Table 4 structurally matches `config.K=10` and the auto-alpha BM25/BGE-M3 path, but `config.STAGE1_TOPN=100` differs from the paper's candidate-pool analysis using N=50 as the main point. The default runner is not verified to reproduce Tables 5 or 8–10, and the paper's Oracle Temporal Filtering is not the same as released best-alpha. No numeric paper parity is claimed; the detailed map is in `timely_compat/qualification.md`.

The paper describes TimelyQABench as a controlled synthetic benchmark: Korean QA pairs generated with Llama-3.3-70B and evolving policy families generated for temporal contrast. It is not a corpus of authentic laws or regulatory filings. Its gold document IDs are official retrieval labels and are described by the authors as minimal answer evidence; independent sufficiency verification remains an optional audit before using them as a human-verified context oracle.
