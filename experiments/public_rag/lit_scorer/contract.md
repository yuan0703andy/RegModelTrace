# LIT-RAGBench A0.4c scoring contract

This contract is fixed before any Track A generator output. The official English dataset has 114 rows. The primary Track A scorer is a **local adaptation**, not the official GPT-4.1-mini score: `Qwen/Qwen2.5-32B-Instruct-AWQ` at immutable revision `5c7cb76a268fc6cfbb9c4777eb24ba6e27f9ee6c`. The official `prompts/evaluation/judge_en.txt` and the official `RAGTask.create_evaluate_messages()` message layout are used unchanged; the local judge receives the same question, reference reasoning, reference answer, positive context, and generated answer fields. The judge response contract is JSON with `score` exactly 0 or 1 and a nonempty `evaluation_reason`. Invalid/missing responses are retained as `INVALID_JUDGE_OUTPUT`, never silently scored zero. The A1 runtime must pin the actual model bytes, tokenizer, vLLM version, decoding configuration, and prompt hash before producing scores. Until then, scorer execution remains unqualified.

The source-only human audit subset is frozen in `audit_subset.json`: 30 distinct zero-based English row indices, selected before generator or judge outputs, six each from I, R, L, T, and A types. Multi-label cases are selected only once in fixed `IRLTA` priority. Each selected answer is independently scored by two humans for correctness from the supplied context, then disagreements are adjudicated without seeing the judge's score. Report judge-human agreement, disagreement by type, invalid JSON rate, and all ambiguous cases. If human agreement is poor or judge disagreements are material, report both human and judge outcomes; do not present an unqualified aggregate model accuracy.

For `FAITHFUL_LIT_RAGBENCH`, preserve the official prompt, combined positive-plus-negative context, global `random.seed(42)` and sequential `random.shuffle`, and explicitly run `--num-tasks 114`; save actual row order and shuffled citation-context order. The official runner's example uses GPT-4.1 generation and GPT-4.1-mini judgment, so changing to local generator/judge must be labeled `LOCAL_GENERATOR_LOCAL_JUDGE_ADAPTATION` rather than a replication of published scores.

For the separately labeled `CONTROLLED_CONTEXT_DIAGNOSTIC`, use the same cases with positive-only, negative-only, and combined conditions and common token budget. Context ordering is per case/condition: seed is the first 64 bits of SHA-256(`RegModelTrace-LIT-controlled-order-v1|en|<row_index>|<condition>`), interpreted as an unsigned big-endian integer. Use that seed with a local Python `random.Random(seed)` instance; save the ordered source chunk indices. This is not the official global-seed ordering and never enters a faithful leaderboard.

No model/judge run or human scoring has occurred in A0. The frozen subset is a sampling plan, not a qualification result. A1 is a separate authorization and runtime freeze.

Primary source: Koki Itai et al. (2026), *LIT-RAGBench: Benchmarking Generator Capabilities of Large Language Models in Retrieval-Augmented Generation*, LREC 2026 / arXiv:2603.06198, https://arxiv.org/abs/2603.06198 ; pinned code https://github.com/Koki-Itai/LIT-RAGBench/tree/5c3f30d924bc1615c08eb85f560f3aceb2fac7d4 .
