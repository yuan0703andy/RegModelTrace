# TimelyQABench A0.4b project split

The frozen upstream archive contains 12,000 rows: 3,000 per domain, with ten nested Korean documents per row. The released `global_doc_id` values are distinct within each domain, but that does **not** imply independent text. An exact UTF-8 document-text SHA-256 audit found 397 document hashes shared across rows and one connected overlap component of 486 rows. The reviewer-proposed row-level hash split would therefore leak identical documents across development and confirmation.

`freeze_timely_split.py` unions all rows sharing any exact document text across all four domains, then assigns whole connected components to a project-defined split. It places components larger than ten rows in development and assigns remaining components by a deterministic salted hash within the dominant domain/category stratum. This yields 9,699 development and 2,301 confirmation rows, 11,470 components, zero exact document-text cross-split overlap, and assignment SHA-256 `5787ba3a5adc0e1d423a7805283f468d18e3f54166c1580c22d6633ab4ce4c07`. The 486-row giant component is development-only, so confirmation does not sample it. Rare one-row category labels cannot contribute to both splits. Both limitations remain visible in `split_manifest.json`.

This split was frozen before any Track A model output. It is **not** an official TimelyQABench split. Exact-text isolation does not prove independence from paraphrases, common synthetic templates, or repeated topics. Those risks require a separate sensitivity audit if a later claim depends on independence beyond exact bytes. The original released dataset remains byte-identical and outside Git; this derived assignment references only row identities and overlap-component IDs.
